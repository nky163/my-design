Design Rule — 制約仕様

デザインルール

部品の一覧は配らない。決めるのは制約だけで、部品はデッキごとにその場で作る。この文書が定義する部品クラスは0個。中身は2種類しかなく、どちらに属するかで扱いが正反対になる。

ゾーン中身扱い
固定ゾーントークン・骨格・影・キー送り（02章）このCSSをそのままコピーする。変えない。
自由ゾーン部品・図・1枚の構成（03〜06章）その場で作る。以下の制約内で自由。

ファイルは2つ。design-rule/rules.html がこの文書（正本）、design-rule/sample.html が見本デッキ13枚。見本はここに書いたルールだけで組んである。

01何のための型か

デッキは必ずどちらかのモードに属する。共通の骨格は同じで、モードで変わるのは次の6行だけ。

項目LT登壇読解メモ
1枚の情報量見出し＋部品1つ＋一文1枚で完結。本文は長くてよい
出典任意必須
締めの一文必須。ただし表紙と締めの1枚は除く使わない
.slide の余白4.4cqw 5.2cqw 6cqw3.6cqw 5.2cqw 5.2cqw
本文の段M ＝ 1.8cqwS ＝ 1.2cqw
.footlogo0.8cqw ／ 800 ／ --ink でデッキ名0.8cqw ／ 400 ／ --ink-3 で原典URL

この6行は02章の骨格を書き換えて適用しない。上書きは1枚ずつ <section class="slide"> の側で行う。余白は <section class="slide" style="padding:3.6cqw 5.2cqw 5.2cqw"> のようにその枚に直接書く。サイズ・太さ・色は、その枚にモードのクラスを足して（例 class="slide note"）.slide.note h2{ font-size:1.8cqw; } .footlogo.src{ font:400 .8cqw …; color:var(--ink-3); } のように、骨格の後ろに数行の上書きを置く。引用ブロックそのものは1文字も変えない。

判定はこの一点だけ — その1枚は、見出しと部品1つと一文で言い切れるか。
言い切れないなら、足すのではなく2枚に割る。

02そのままコピーする骨格

ここは読まずに写すところ。写すのはCSS・HTMLの外枠・キー送りの3つで、1文字も変えない。16:9のステージを1つ作り、中は container query 単位（cqw）だけで組む。rem や px を混ぜた瞬間に比率が崩れる。書体の読み込み1行は04章。

:root{
  --surround:#171410; --paper:#F8F6F2; --card:#FFFFFF;
  --ink:#26333F; --ink-2:#4E5F60; --ink-3:#8B98A4;
  --line:#E6E1D9; --fill:#F1ECE4;
  --accent:#D9822B; --neg:#DC4A4A; --pos:#12776A;
}
*{ box-sizing:border-box; }
body{
  margin:0; background:var(--surround); color:var(--ink);
  font-family:"Lato","Zen Kaku Gothic New","Noto Sans JP",sans-serif;
  display:flex; align-items:center; justify-content:center; min-height:100vh;
}
.deck{
  position:relative;
  width:min(100vw, 177.78vh); height:min(56.25vw, 100vh);
  container-type:size; overflow:hidden;
  background:var(--paper);
  outline:none;
}
.slide{ position:absolute; inset:0; display:none; flex-direction:column; padding:4.4cqw 5.2cqw 6cqw; }
.slide.is-active{ display:flex; }
.deckfoot{ position:absolute; right:5.2cqw; bottom:2.2cqw; font:400 .8cqw "Lato",sans-serif; color:var(--ink-3); font-variant-numeric:tabular-nums; }
.footlogo{ position:absolute; left:5.2cqw; bottom:2.2cqw; display:flex; align-items:center; gap:.5cqw; max-width:70%; }
.reveal{ opacity:0; transform:translateY(.6cqw); animation:revealIn .55s cubic-bezier(.2,.7,.3,1) forwards; animation-delay:calc(var(--i,0) * .12s); }
@keyframes revealIn{ to{ opacity:1; transform:none; } }
@media (prefers-reduced-motion:reduce){ .reveal{ animation:none; opacity:1; transform:none; } }

HTML の外枠。<body> の中はこの形にする。id="deck" を落とさない — 下のキー送りが getElementById('deck') でこれを掴むので、id が無いと読み込みの時点で落ち、送りが全部死ぬ。

<div class="deck" id="deck">

  <section class="slide is-active">
    <h2 class="reveal" style="--i:0">見出し</h2>
    <div class="footlogo">デッキ名</div>
    <div class="deckfoot">01 / 13</div>
  </section>

  <section class="slide">
    …
  </section>

</div>

キー送り。</body> の直前に置く。矢印キーと空白で送る。これも変えない。

<script>
(function(){
  var slides = Array.prototype.slice.call(document.querySelectorAll('.slide'));
  var i = 0;
  var deck = document.getElementById('deck');
  function render(){
    slides.forEach(function(s, idx){ s.classList.toggle('is-active', idx === i); });
  }
  function go(d){
    var n = i + d;
    if(n < 0 || n >= slides.length) return;
    i = n; render();
  }
  window.addEventListener('keydown', function(e){
    if(e.key === 'ArrowRight' || e.key === ' '){ go(1); e.preventDefault(); }
    if(e.key === 'ArrowLeft'){ go(-1); e.preventDefault(); }
  });
  deck.setAttribute('tabindex', '0');
  render();
})();
</script>

この3つを写せば、それで動くデッキになる。あとは中身を入れるだけ。is-active は1枚目にだけ足す（送りはこのクラスの付け替えで動く）。動きは class="reveal" と style="--i:N" だけで、これ以上増やさない。ページ番号は .deckfoot（右下）、デッキ名か原典は .footlogo（左下）に置く — どちらも位置だけが骨格で決まっており、中身と見た目は01章のモードの表に従う。なお骨格は base の font-size を持たないので、サイズを書かない要素はブラウザ既定の16px（cqw に追従しない固定値）で描かれる。文字を置く要素には必ず04章の5段のどれかを明示する。

03色

色はこの11個。外に色は作らない。地は純白にしない。ダークモードには対応しない — 会場のプロジェクタで白地に映す前提なので prefers-color-scheme は書かない。

トークン値役
--surround#171410ステージの外側。16:9の外に出る余りの地
--paper#F8F6F21枚の地。純白にしない。ここが温かいだけで印象が決まる
--card#FFFFFF地の上に置く面。地との差はこの一段で足りる
--ink#26333F見出しと本文。黒ではなく紺寄り
--ink-2#4E5F60説明文・補足。面の中の本文はこれ
--ink-3#8B98A4出典・ページ番号・ラベル。読ませない文字
--line#E6E1D9罫線。区切りたいだけのときはまずこれ
--fill#F1ECE4塗りの面。地とカードの中間の温度。図に寒色の面を置かない
--accent#D9822B強調。1枚に1役だけ
--neg#DC4A4ABefore 側のみ
--pos#12776AAfter 側のみ
accent は1枚1役。「表紙タイトルの罫」「見出しの罫」「選んだ1行」「数字の単位」「締めの一語」のどれかひとつに絞る。役は枚ごとに選び直してよいが、1枚のなかで2つ持たせると、どこを見ればいいか分からなくなる。
neg / pos は Before / After 専用。強調にも、良し悪しの色分けにも使わない。

淡い面が要るときは rgba(<トークンの値>, α) で作る。不透明の中間色を作らない。淡いオレンジの面なら rgba(217,130,43,.08)、その縁なら rgba(217,130,43,.28) のように、同じ1色から濃さだけを変える。中間色を混ぜて新しい色名にすると、地の色を変えたときにその面だけ一緒に動かなくなる。

04文字

書体は "Lato","Zen Kaku Gothic New","Noto Sans JP",sans-serif の1行だけ。Lato は和字を持たないので、欧文と数字だけが Lato で描かれ、和文はその次の Zen Kaku Gothic New に落ちる（無い環境では Noto Sans JP）。順番がそのまま仕組みで、入れ替えると欧文まで和文書体で描かれる。読み込みは <head> に1行:

<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Zen+Kaku+Gothic+New:wght@400;500;700;900&family=Lato:wght@400;700;900&family=Noto+Sans+JP:wght@400;500;700&display=swap">

サイズは5段。段の間の値は作らない。

段値LT登壇での役読解メモでの役
XS0.8cqw出典・ページ番号・ラベル出典・ラベル
S1.2cqw表・コード・凡例・図キャプション本文
M1.8cqw本文・締めの一文見出し
L2.8cqw見出し表紙タイトル
XL5.2cqw表紙タイトル使わない

★ この5段はここで課している制約で、実物から観測したものではない。測った4つの実物デッキは、1デッキあたり20〜33種類の文字サイズを使っていた。揃える基準が無かったので、5段に絞って上から与えている。

等幅書体はコードにだけ使ってよい。スタックは "SFMono-Regular",Menlo,Consolas,monospace、サイズは5段の中（コードは S ＝ 1.2cqw）。コード以外の文字を等幅にしない。

051枚の作り方

1枚に載る量の上限はモードで決まる。LT登壇は見出し＋部品1つ＋一文まで。読解メモは1枚で完結してよく、本文は長くてよいが出典を必ず持つ。どちらも、上限を超えたら足すのではなく割る。以下は両モード共通。

  • 余白 — 左右は両モードとも 5.2cqw。上下だけがモードで変わる（01章の表）。この線の外に文字も面も出さない。
  • 単位 — cqw のみ。例外は2つ、border の 1px と、丸い形を作るときの border-radius:999px だけ（丸めきる指定なので cqw で書くと意味のない大きな数になる）。それ以外の角丸も線幅も cqw で書き、rem / px / vw を混ぜない。
  • 影 — 次の2段だけ。drop-shadow は使わない。3つ目の選択肢は影を使わないことで、区切りたいだけなら background:var(--fill) のほうが静かに済む。迷ったら影なしを選ぶ。
段値使う場面
弱box-shadow:0 .12cqw .8cqw rgba(38,51,63,.06)地の上に置いた面。浮かせるためではなく、輪郭を落とすために使う
強box-shadow:0 .2cqw 1cqw rgba(38,51,63,.14)1枚に1つだけ、いちばん見てほしい面に。2つ置くと効かなくなる
部品はデッキごとに作る。そのデッキのファイルの中だけに置き、他のデッキへ持ち出さない。デッキをまたいで共有してよいのは、02章の骨格と01章のモードの契約だけ。
1つのデッキの中でなら、枚をまたいだ再利用をしてよい。55枚のデッキで同じ形に毎回別の名前を付けて書き直すのは、CSSとして悪いうえに、じきに誰も守らなくなる — 守られなくなったルールが実態から離れていくというのが、旧文書の壊れ方だった。
避けたいのはデッキ間のカタログ化のほう。決まった部品一式を配ると、どのデッキも要らなかった部品まで相続し、直せないまま腐っていく。
見本 design-rule/sample.html は部品を1枚ずつ作り分けているが、あれは考え方を限界まで押した実演であって、ここで課している水準ではない。

06図

図の描き方は決めない。守るのは4行だけ。

  1. 色 — 03章の11トークンと、その rgba だけ。図のためだけの色を作らない。
  2. 作り — div ＋ flex でも SVG でもよい。図らしく見せるために SVG を選ぶ必要はない。四角と線と文字で足りるなら div のほうが速く、崩れにくい。
  3. 説明文 — 図の中に書かない。figcaption か本文へ出す。図の中に置くのは短いラベルだけで、図が単体で意味を持たなくてよい。
  4. 線 — 太線と基本線の2種まで（例: .4cqw と .2cqw）。破線が要るなら、この2種のどちらかの見た目を変えて作り、3本目の太さを増やさない。線幅も cqw で書く — 矢印の marker は既定が markerUnits="strokeWidth" で線幅に比例するので、線幅を px にすると矢印の頭だけが固定寸法になり、コンテナの大きさを変えたときに図の他の部分と比率が合わなくなる。
SVG に viewBox を付けない。viewBox があると CSS の font-size が viewBox の変換でそのまま拡大されるので、font-size:.8cqw と書いても .8cqw では描かれず、5段のスケールが黙って壊れる。<svg> の幅と高さは cqw で与え、中の座標は % で書く。

ダークモードに対応しない（03）12/12満たす。4デッキとも prefers-color-scheme を1度も書いていない

02章の骨格と実物の差分

「骨格をそのまま使っている」が読みで割れるのは、実物の外し方が一様だからで、ばらついているからではない。4デッキが同じ場所を同じように外している。

.deck の寸法・container-type・.slide.is-active・.reveal・@keyframes4/4 が完全一致骨格として機能している
body{ font-family } の1行4/4 が "Lato","Noto Sans JP" に縮め、Zen Kaku Gothic New は h1,h2,h3,b,strong に別立てする★これは新しく課す制約。04章は1行のままを求めている
:root の --surround4/4 が定義せず、body に #171410 を直書き値は同じ。トークン化は★新しく課す
.slide{ padding }LTの2デッキは一致。読解メモの2デッキは骨格側で 3.6cqw 5.2cqw 5.2cqw に書き換えている値は01章の表と一致。置き場所だけが違う（01章は枚ごとの上書きを求めている）
そのほか3/4 が .deck に radial-gradient を重ね（sdlc のみ一致）、4/4 が .deckfoot／.footlogo の bottom を 2cqw か 2.3cqw にし、4/4 がキー送りに同じ拡張を足している記録のみ。ルールは変えない

0件だったルールの扱い

どの実物も満たさなかったルールは5つ。うち4つは残し、1つは緩めた。
残した4つは意図して課す制約なので、上の2つの表に ★これは新しく課す制約 と印を付けた — ①文字サイズを5段に絞る（04章、承認済み）／②SVG に viewBox を付けない（06章）／③body の書体スタックを1行のまま使う（02・04章）／④--surround をトークンとして持つ（02・03章。4デッキとも #171410 を直書きしている。値は同じなので、変わるのは地の色を変えたときに1箇所で済むかどうか）。この4つは既存デッキをこのルールで測ると必ず落ちる。新しく組むデッキにだけ課す。
緩めたのは「部品クラスをその1枚のために作る」（05章）。12枚が全滅したのは実物の側の問題ではなく、ルールが本来の狙いより広く網を掛けていたから。配るまいとしていたのはデッキ間のカタログで、1つのデッキの中の再利用は最初から禁じる対象ではなかった。05章をデッキ単位に書き換えた。
ルールごと削ったものは無い。旧文書の「図はSVGで描く」のような実態に反する条文は、今回の12枚からは出なかった（memo と agentic-qa は SVG を1つも持たず、sdlc と newrelic の図も大半が div＋flex だが、06章は既に「div でも SVG でもよい」と書いてある）。

3〜4デッキが共通でやっているのに、ここに書いていないこと

逆向きの抜けも探した。次の3件は実物の 4/4 が共通でやっているが、この文書は何も言っていない。今回はルールとして足していない — 記録だけ残す。

  • クリックで送る（4/4）— 左右14%の当たり判定、丸い prev／next ボタン、3.2秒で消える操作ヒント、deck.focus()。02章のキー送りは矢印キーと空白だけで「これも変えない」と書いてあるが、実物は4つとも同じ拡張をしている。
  • 数字に font-variant-numeric:tabular-nums（4/4）— 骨格は .deckfoot にだけ付けているが、実物は数値カード・年号・順位にも付ける。04章は数字の扱いを何も書いていない。
  • 表紙 s-cover と締め s-close という2つの特別な枚（4/4。newrelic はさらに章扉 s-section を3枚持つ）— 01章は「表紙と締めの1枚は除く」と例外として触れるだけで、この2枚が構造として存在することを書いていない。
検証に使った4デッキ（memo/ 31枚、agentic-qa/ 27枚、sdlc-vibe-coding/ 55枚、newrelic-ai-coding-2026/ 19枚）はこのルールより前に作られたもので、検証のために1文字も直していない。

python3 tools/check-rules.py --baseline <deck> で再現できるのは骨格の行だけ — 4デッキとも骨格の指摘が0件で、これが上表の「12/12（機械チェック）」にそのまま当たる。それ以外の行は12枚を読んで数えたもので、このコマンドとは数が合わない。コマンドはデッキ全体を見るので、選ばなかった枚の違反まで数えるため（例: sdlc 全体ではパレット外の色が2件出るが、#FCF0E2 は選ばなかった8枚目にあり、#FCF4EA は .bx-a に定義されているだけでどこからも使われていない）。SVG の中の font-size:14px のような px はこのコマンドがそもそも見ていない。

このルールの実装例は design-rule/sample.html（13枚）。各枚は、その枚が説明しているルールで自分自身が組んである。見本の部品クラスは1枚ずつ作り分けてあり、枚をまたいで共有しているものは0個 — ただしこれは考え方を限界まで押した実演で、05章が課している水準ではない。05章が求めるのは「部品をデッキの外へ持ち出さない」ことだけで、1つのデッキの中での再利用は妨げない。
