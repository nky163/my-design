# デザインルールの再構築 — 設計

日付: 2026-09-02

## 目的

スライドデッキの設計ルールを、**部品カタログから制約仕様へ**作り替える。
Claude がルールを読んで、その場に合った部品と図を生成できる形にする。

## 背景（実測）

現行は `paper-rule` / `dojo-rule` / `ledger-rule` / `theorem-rule` の4文書。
実物のデッキは `memo` / `agentic-qa` / `sdlc-vibe-coding` / `newrelic-ai-coding-2026` の4つ。

測って分かったこと:

1. **文書化された部品を実物が使っていない。** `paper-rule/rules.html` が定義する
   `.highlight` `.cclose` `.refbox` `.figrow` `.figcard` `.rightUI` `.s-section`
   `.points` `.three` `.four` `.figcaption` は `sample.html` での使用回数ゼロ。
   実物4デッキは `.pcard` `.steps` `.takeaway` を一度も使わず、独自の語彙で書かれている。
2. **骨格・トークン・書体は動いていない。** 8デッキ全部が
   `.deck`（16:9 + `container-type:size`）、`.slide{position:absolute;inset:0;display:none;flex-direction:column}`、
   横 padding `5.2cqw`、`is-active` + キー送り、`.reveal`、
   3書体（Zen Kaku Gothic New / Lato / Noto Sans JP）を共有している。
6. **ただしタイプスケールは不変ではない。** font-size の異なり数は
   memo 25 / agentic-qa 20 / sdlc 29 / newrelic 33 種類。スケールではなく都度指定。
7. **影は2段でほぼ不変。** 実物4デッキ全部が `0 .12cqw .8cqw rgba(38,51,63,.05〜.08)` と
   `0 .2cqw 1cqw rgba(38,51,63,.14)` を共有。`drop-shadow` の使用はゼロ
   （現行 §05 の「drop-shadow系」は実態と逆）。
8. **`.footlogo` はドリフトではなくモード差。** 読解メモ2つが `400 .78cqw` / `ink-3`（出典URL）、
   解説2つが `800 .9〜1cqw` / `ink`（デッキロゴ）。
3. **図の色は100%パレット準拠。** 図の中の生 hex 値（`#26333F` `#8B98A4` `#D9822B`
   `#4E5F60` `#E6E1D9` `#F1ECE4` `#DC4A4A`）はすべてトークンと一致。パレット外の色はゼロ。
4. **「図はSVGで描く」は守られていない。** `memo` と `agentic-qa` は SVG ゼロ・図なし。
   `sdlc` は SVG 7 / div図 10 の混在、`newrelic` は div 主体。
5. **コピーはズレる。** 同一のはずだった固定ゾーンで、`paper-rule` だけ
   `.reveal` が `.6s/.14s`（他3つは `.55s/.12s`）、トークンが11個（他3つは10個）。

→ ルールにすべきは 2・3・7。1 と 4 は削る。5 は文書を1つにする根拠。
  6 と 8 は下の D3a / D4 で扱う。

## 決定事項

### D1. 文書を2ゾーンに割る

| ゾーン | 中身 | 指示 |
|---|---|---|
| **固定** | `:root` トークン / `.deck` / `.slide` / `.deckfoot` / `.reveal` / キー送り / 影の2段 | そのままコピーする。変えない |
| **自由** | 部品・図・1枚の構成・背景のにじみ | その場で作る。制約内で自由 |
| **モード依存** | `.slide` padding / `.footlogo` / 1枚の情報量 / 出典 / 締めの一文 | D4 の表から選ぶ |

### D2. 文書は1つ

`design-rule/rules.html` 1本に統合し、LT と読解メモは「2つのモード」節（D4の表）で書き分ける。
根拠: モード差は4行しかなく、95%が共通。1→2 の分割は後からいつでもできるが、
2→1 の統合はズレた後だと差分照合が要る（実測5番がその実例）。

### D3. 固定ゾーンの正準値

ドリフトしていた値の採用:

| 項目 | 採用値 | 理由 |
|---|---|---|
| `.reveal` | `.55s` / `.12s` | 実物4デッキ全部とルール3つが一致。`paper-rule` のみ逸脱 |
| 色トークン | 10個（`--paper --card --ink --ink-2 --ink-3 --line --fill --accent --neg --pos`） | 8デッキ中7つが10個 |
| 横 padding | `5.2cqw` | 8デッキ完全一致 |
| 背景のにじみ | **自由ゾーンに移す** | 実物で0/1/1/2本とバラバラ。不変ではない |
| `.deckfoot` | `bottom:2.2cqw` / `font:400 .82cqw` / `ink-3` / `tabular-nums` | 4デッキで .8〜.85cqw の誤差のみ。中央値を採る |
| `.footlogo` | **モード依存に移す** | 役割が違う（D4 参照）。ドリフトではない |
| 影 | 2段のみ。弱 `0 .12cqw .8cqw rgba(38,51,63,.06)` / 強 `0 .2cqw 1cqw rgba(38,51,63,.14)` | 実物4デッキが共有。`drop-shadow` は使わない |

`--accent-wash` 等の派生色は自由ゾーン（必要なら各デッキで定義する）。

### D3a. タイプスケール（★新しく課す制約 — 観測ではない）

実物は font-size を 20〜33 種類も使っており、共有スケールは存在しない。
「Claude がよしなに生成する」ためには段が要るので、**5段のスケールを新設する**。
これは実物から観測された不変ではなく、こちらから課す新しい制約。

| 段 | 値 | LT登壇での役割 | 読解メモでの役割 |
|---|---|---|---|
| XS | `0.8cqw` | 出典・ページ番号 | 出典・ラベル |
| S | `1.2cqw` | — | 本文 |
| M | `1.8cqw` | 本文・締めの一文 | 見出し |
| L | `2.8cqw` | 見出し | 表紙タイトル |
| XL | `5.2cqw` | 表紙タイトル | — |

段の外の値を使わない。LT の文字が大きいのは、1枚に載る量が少ないから。

書体は実物どおり据え置き（不変が確認できているため）:
`"Lato","Zen Kaku Gothic New","Noto Sans JP",sans-serif` の順。
この順で書くと欧文だけ Lato になる。

### D4. 2つのモード

| | LT登壇 | 読解メモ |
|---|---|---|
| 1枚の情報量 | 見出し＋部品1つ＋一文 | 1枚で完結。本文は長くてよい |
| 出典 | 任意 | 必須（`footlogo` に原典URL） |
| 締めの一文 | 必須 | 不要 |
| `.slide` padding | `4.4cqw 5.2cqw 6cqw` | `3.6cqw 5.2cqw 5.2cqw` |
| `.footlogo` | `800 .9cqw` / `--ink` / デッキ名 | `400 .78cqw` / `--ink-3` / 原典URL |
| 本文の段 | M（`1.8cqw`） | S（`1.2cqw`） |

### D5. 図のルール（4行）

- 色はトークンのみ。生 hex でもよいが、パレット外の色を作らない
- div+flex でも SVG でもよい。図の内容で選ぶ
- 図の中に説明文を書かない。`figcaption` か本文に出す
- 線は太線（`2.4` / `.4cqw`）と基本線（`1px` / `.2cqw`）の2種まで

「SVGで描く」および `.spectrum` `.netdiagram` `.distchart` `.nest` `.loop` `.risk-table`
など、実物での使用実績がない図の型は書かない。

### D6. 文書構成（6章）

```
01 何のための型か（2モード表を含む）
02 そのままコピーする骨格（CSS + キー送り、丸ごとコピー用）
03 色（10トークン、1トークン1役）
04 文字（2書体 + 5段スケール）
05 1枚の作り方（情報量・余白・影）
06 図（4行の制約）
```

現行の「05 影のつくり方」「07 図の描き方の2パターン」「10 ファイル」は畳む。

### D7. ファイル操作

**改名して中身を書き直す**（削除ではないので履歴が残る）
- `git mv paper-rule design-rule`
- `design-rule/rules.html` — 制約仕様（正本）
- `design-rule/sample.html` — 見本デッキ

統合後の文書は LT と読解メモの両方を扱うため `paper-rule` という名前が合わない。
`git mv` で改名すれば、削除するフォルダは承認どおり3つのままになる。

**消す**（git コミット済み・復元可能）
- `dojo-rule/` `ledger-rule/` `theorem-rule/` の3つ

**触らない**（git 未追跡・消すと戻せない）
- `memo/` `agentic-qa/` `sdlc-vibe-coding/` `newrelic-ai-coding-2026/`

現行 §10 が正本と称する `CLAUDE.md` と `index.html` は実在しない。
2ファイル構成（`rules.html` = 正本、`sample.html` = 見本）に直し、この記述は削除する。

## 検証

両方の `sample.html` を書き直すため「サンプルがルールを満たす」は自己採点になる。
かわりに**書き直さない実物4デッキ**（`memo` `agentic-qa` `sdlc-vibe-coding`
`newrelic-ai-coding-2026`）から各3枚を取り、全ルールを当てて確認する。

- どの実物も満たさないルール → 削るか、「新しく課す制約」として明示し承認を取る
- 実物3〜4個が共通で行っているのに書かれていない事柄 → 抜け漏れとして追加
