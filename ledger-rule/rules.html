Dense Report Slide — Design System

Ledger の設計ルール

決算・進捗報告のような、1枚あたりの情報密度が高いスライド向けの16:9設計ルール。指標を並べ、結論を先出しする「BLUF型」。色・書体のトークンは ../design-rule/rules.html（Paper）と共通にし、密度が高い場面向けの使い方だけを足す。

参照：東証グロース上場企業が開示した決算説明資料（2026年8月開示、47ページ）の構成パターンを分析して型を抽出。色・書体は個社のブランドではなく Paper の設計ルールに統一している。見本：sample.html（架空データで組んだ12枚）。

01何のための型か

この型が扱うのは、1枚で言い切れない量の情報。決算数値、進捗率、リスク一覧など、読み手が同時に比較しながら判断する資料が対象になる。Paperの「1枚1部品」ルールとは前提が逆で、こちらは関連する指標はまとめて並べることを許す。

その代わり、結論は必ずヘッダー直下の一文（BLUF＝Bottom Line Up Front）で先に言い切る。
表やグラフは、その一文を裏付ける証拠として後に置く。証拠から結論を推測させない。

02骨格

全ページ共通のヘッダー・フッターで「今どこを読んでいるか」を保証する。47ページを超える資料でも迷わないための最低限の装置。

.deck{ width:min(100vw,177.78vh); height:min(56.25vw,100vh); container-type:size; overflow:hidden; background:var(--paper); }
.slide{ position:absolute; inset:0; padding:4.4cqw 5.2cqw 6cqw; display:flex; flex-direction:column; }

.pagehead{ font-size:2.3cqw; font-weight:700; border-left:.3cqw solid var(--accent); padding-left:1cqw; }  /* Paperのh2と同じ左オレンジ縦罫 */
.bluf{ font-size:1.7cqw; font-weight:700; margin:0 0 1.8cqw; }   /* 結論は見出しの直後、本文より先に置く */
.body{ flex:1; min-height:0; }                                        /* ここに複数コンポーネントを並べてよい */

.chapter-tab{ position:absolute; top:4.4cqw; right:1.2cqw; writing-mode:vertical-rl; font-size:.85cqw; color:var(--ink-3); }
.deckfoot{ position:absolute; right:5.2cqw; bottom:2.2cqw; font-size:.85cqw; color:var(--ink-3); }

右端の縦書き.chapter-tabは現在の章名を常時表示する。ページを飛ばして読む前提の資料だからこそ、章の目印をページ内に埋め込む。

03色

トークンは Paper と同じもの（同じ名前・同じ値）を使う。Ledger独自の色は増やさない。違うのはトークンの役割の割り振り方だけ。

--paper

#F8F6F2

地。純白にしない

--card

#FFFFFF

KPIブロック・表・カードの面

--ink

#26333F

見出し・本文・表の数値・チャートの主系列

--ink-2

#4E5F60

補足・キャプション・KPIの増減率

--ink-3

#8B98A4

ラベル・ページ番号・章タブ

--fill

#F1ECE4

表ヘッダーの地・チャートの非主系列の面

--line

#E6E1D9

罫線・カード枠

--accent

#D9822B

1枚に1役だけ。見せたい1列・1本の線・1つの数字

--neg

#DC4A4A

Before（期首・変更前）側のみ

--pos

#12776A

After（今期・変更後）側のみ

Paperは「1枚に1役」だが、Ledgerは1枚に指標が何個も乗る。だからaccentの節約は「1スライドに1役」から「1コンポーネントに1役」に読み替える——表なら見せたい列1つ、チャートなら線1本、KPIグリッドなら「重要指標」タグの付いた1枚だけ。それ以外の数字・棒・見出しはすべて --ink / --ink-2 の無彩色で構造化する。オレンジを増やして目立たせるのではなく、オレンジ以外を減らして目立たせる。

赤・緑（--neg / --pos）は Paper と同じく、時点や状態を明示的に対比するときだけに絞る。KPIの増減が良いか悪いかを色では示さない（詳しくは05章）。

04文字

Paperと同じ2書体。和文の見出しは Zen Kaku Gothic New、欧文と数字は Lato。本文の和文は Noto Sans JP に落ちる。金額や％は縦に並ぶことが多いので font-variant-numeric: tabular-nums で桁を揃える。

05数字の見せ方

この型でいちばん誤解されやすい部分。色で善し悪しを判断させない。同じページに「伸びている指標」と「投資で一時的に落ちている指標」が同居するのが決算資料の常だから、両方を等しく無彩色で扱い、解釈は文章（BLUF）に語らせる。

やる

  • 増加は「+」、減少は「▲」の記号だけで示す
  • 増減率の色は good/bad にかかわらず --ink-2 で統一（accentすら使わない）
  • 3桁ごとにカンマ区切り、単位は数字の直後に小さく添える
  • 比較の基準（前年・計画比）を数字のすぐ横に明記する

やらない

  • 減少した数値だけ --neg（赤）にする
  • 伸びている数値を --pos（緑）や --accent で強調する
  • ▲を使わず「-25%」のように符号を省略する

06表

見出し行は--fill の地に --ink の太字。白地に色文字より、この温度差だけで十分読める（Paperの「地とカードの2段で差をつける」と同じ考え方）。読ませたい1列（進捗率など）だけ--accent の文字色にして視線を集める。単位は表の右下に1回だけ書く。

th{ background:var(--fill); color:var(--ink); border-bottom:2px solid var(--line); }
td.highlight{ color:var(--accent); font-weight:700; }   /* 読ませたい列だけ */
td.num{ font-family:"Lato"; font-variant-numeric:tabular-nums; text-align:right; }

07チャート

チャートは3種類に絞る。色は棒・面はすべて --ink（無彩色）、accentは線1本か、注目させたい1点だけに使う。2色以上の系列を塗り分けで見せない。

積み上げ比較

2時点の内訳を並べて増減を見せる。区分は3つまで、色は --ink の濃淡（--ink / --line / --fill）だけ。

棒＋線コンボ

実額の棒は --ink、率の線だけ --accent。色ではなく「棒 vs 線」という形の違いで系列を分ける。

09ルール

やる

  • 関連する指標はまとめて並べる（比較が目的なら分割しない）
  • 結論の一文はヘッダー直下に先出しする
  • 表・チャートの構造色は --ink、accentは1コンポーネントに1役だけ
  • KPIの増減率はすべて --ink-2 に統一する
  • 装飾はカバーとセクション扉だけに使う

やらない

  • ネガティブな数値のためだけに --neg（赤）を使う
  • 本文ページに装飾グラフィックを置く
  • 1枚のチャートに --ink 以外の色を2つ以上増やす
  • 疑似3Dの影や立体表現でデータを飾る
  • 単位をタイトルだけに書いて数字から省く
